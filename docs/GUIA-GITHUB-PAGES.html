Pega estos tres datos de Firebase. Este formulario genera archivos en tu ordenador; no envía estos datos a ningún servicio.

Copia las reglas de arriba en Realtime Database → Rules → Publish. Coloca el archivo descargado en docs, sustituyendo firebase-config.js.

Publicar en GitHub Pages

Esta versión se ejecuta en GitHub Pages. No utiliza Render, Docker ni un servidor Node en Internet.

Firebase recibe los votos de los móviles y permite actualizar la nube. Al acabar, descargas un Excel (.xlsx) con palabra, votos, porcentaje, pregunta y fecha. Los votos no se escriben en GitHub.

1. Preparar Firebase (una sola vez)

1. Abre https://console.firebase.google.com/ y crea un proyecto. Mantén el plan gratuito Spark. No necesitas activar Analytics.

2. En Build → Authentication → Get started → Sign-in method, activa Email/Password para el organizador. No necesitas activar Anonymous.

3. En Authentication → Users → Add user crea tu cuenta de organizador con correo y contraseña. Copia su UID. Guarda la contraseña para entrar en la aplicación; no la pongas en GitHub ni en la configuración.

4. En Build → Realtime Database → Create database crea la base en modo bloqueado. Si está disponible, elige una región europea. Copia la URL que termina en firebaseio.com o firebasedatabase.app.

5. En Project settings → General → Your apps registra una aplicación web (icono </>). No actives Firebase Hosting. Copia el valor apiKey de firebaseConfig. Es configuración pública de la app.

6. Abre GUIA-GITHUB-PAGES.html: su formulario genera firebase-config.js y las reglas. También puedes editar docs/firebase-config.js manualmente (apiKey y databaseURL).

7. En FIREBASE-REGLAS.json sustituye TODAS las apariciones de PEGA_AQUI_EL_UID_DEL_ADMIN por el UID del paso 3. Copia el documento completo en Realtime Database → Rules y pulsa Publish. El formulario de la guía hace esta sustitución por ti.

8. En Authentication → Settings → Authorized domains añade imf93.github.io.

2. Subir los archivos a GitHub

1. Descomprime el ZIP. Copia la carpeta docs completa dentro de tu carpeta local del repositorio palabra-viva. Sustituye docs/firebase-config.js por el que acabas de generar.

2. En GitHub Desktop selecciona palabra-viva. Escribe «Versión GitHub Pages» en Summary, pulsa Commit to main y después Push origin.

3. Abre el repositorio en GitHub. Con GitHub Free, Pages necesita un repositorio público. Tu captura lo mostraba privado. Si quieres hacerlo público, revisa primero los archivos e historial que se harán visibles y utiliza Settings → General → Danger Zone → Change repository visibility. Si quieres conservarlo privado, crea otro repositorio público que contenga solamente esta carpeta docs; el nombre de ese repositorio será parte de la dirección web.

4. En Settings → Pages selecciona Source: Deploy from a branch; Branch: main; Folder: /docs; pulsa Save.

5. Espera a que GitHub muestre la dirección. Si el repositorio se llama palabra-viva y pertenece a imf93, será https://imf93.github.io/palabra-viva/ . No incluyas /docs en la dirección.

No subas el ZIP como archivo único: hay que subir su contenido. La carpeta docs contiene la web ya compilada; no tienes que ejecutar comandos ni instalar programas.

3. Usar la aplicación

1. Abre la dirección de GitHub Pages e inicia sesión con el correo y la contraseña del organizador.

2. Pulsa Nova pregunta, escribe la pregunta y entre 2 y 100 palabras, una por línea (máximo 40 caracteres por opción).

3. Pulsa Obre la votació y Projecta. Se muestran los logos, la pregunta, la nube y el QR con PARTICIPA. Esc sirve para salir de pantalla completa.

4. Cada participante escanea el QR y escoge una palabra. También puedes compartir el enlace desde el panel. No se pide correo ni contraseña a los participantes.

5. La nube consulta los resultados aproximadamente cada 2 segundos mientras hay conexión.

6. Pulsa Tanca la votació y Descarrega Excel para obtener el recuento definitivo. Puedes exportar durante la votación, pero será una instantánea provisional.

El Excel queda en las descargas de tu ordenador. No se actualiza solo después de descargarlo. Los datos de trabajo permanecen en Firebase hasta que los borres desde la consola, después de exportar; no hay borrado automático. Esta versión no importa las preguntas de la versión local/Render anterior: crea la pregunta en la nueva web.

4. Comprobación antes de la sesión

Haz una pregunta de prueba y vota desde dos móviles: comprueba que el total sea 2, que crezca la palabra seleccionada, que al cerrar ya no se acepten votos y que el Excel coincida. Reabre la página desde su enlace para comprobar que sigue funcionando. La configuración de tu cuenta Firebase y la publicación deben completarse antes de esta prueba real.

Los participantes no crean cuentas ni identidades anónimas. Cada envío cuenta como una respuesta: una persona puede volver a abrir el enlace y responder otra vez. La aplicación no limita respuestas por persona. El límite de altas anónimas por IP ya no interviene. Esto no garantiza por sí solo la capacidad para 800 participantes; la capacidad real no se ha validado.

Ayuda

- Pantalla de configuración: comprueba docs/firebase-config.js y que se haya enviado con Push origin.

- Error de permisos al entrar: revisa el UID en las reglas y el usuario organizador. El UID no es el correo.

- QR que no abre: comprueba que lo has generado desde la dirección pública de GitHub Pages, no desde localhost.

- No aparecen votos: comprueba que la votación esté abierta y que hayas publicado las nuevas reglas de Firebase.

- Una contraseña nunca va en firebase-config.js. No se necesita ningún archivo de cuenta de servicio.
